## Risks register

1. **Runner-image drift + alias remap (measured live: windows-latest now
   resolves to the VS-2026 variant image).** The image's VS/SDK/Clang rows
   roll monthly and the alias itself remaps silently. The series guards
   (condition 2) turn any remap/drift into a red build naming the measured
   value, never a silent toolchain swap; residual: the job reds until
   re-pinned/re-guarded (accepted — the N3 precedent, the same posture the
   Gradle 9.9-series guard took).
2. **Unverified-at-gate execution facts.** No windows job exists yet; the
   vcvars/cl-on-PATH behavior, the MSVC cdylib link, and the console
   encoding of the headless smoke are verified only at the first live run.
   Mitigation: the guards are fail-closed with measured-value output; the
   honest record is the precedent (N3's eleven rounds).
3. **Blind authoring (the accepted demo-standard trade).** No local
   verification AT ALL (no mingw in-sandbox, no desktop) — the C++ code
   lands authored against the header's documented contract and is proven
   only CI-side. A contract misread (freeing last_error, caching the borrow,
   mixing allocators) surfaces as a CI-side crash rather than a local one.
   Mitigations: the RAII discipline (condition 3) makes the two safe-by-
   construction; the boundary battery running ON WINDOWS (the real ABI
   verification) exercises the same cdylib the .exe links.
4. **CRLF/console-encoding traps in the expected-text diff.** pwsh/cmd
   redirection is UTF-16/CRLF-prone and the MSVC CRT translates \n→\r\n in
   text mode — the full-stdout diff against the committed expected text
   must pin a binary-safe output mode + a byte-exact compare (Git-for-
   Windows `bash` + `diff -u`, the Linux precedent) or the smoke reds/
   false-passes on encoding, not content. (ENG lane detail crossing my
   diff-correctness view.)
5. **The rider's supersession is posture-dependent.** It holds exactly
   while the runtime classpath stays zero-external and the plugins stay
   exactly pinned. Any future runtime external (an AndroidX join at a GA
   lane, say) re-opens the lockfile question by construction — the
   supersession record must carry that trigger (condition 5).
6. **512 MiB is a RAM hazard in its own right** on a memory-constrained
   host (the N3 register's Android note applies to Windows verbatim) — a
   512 MiB read can OOM a small VM before any engine bound trips. Accepted
   for the demo (the uniform bound is the recorded policy; the app-side
   pre-read refusal is the honest UX, the boundary the backstop).

   dwrite, comdlg32, clearfile_core_ffi.dll} — no winhttp/wininet/ws2_32/
   shell-open imports. That turns the "no network" honesty claim into a
   checkable CI assertion for ~zero cost.
2. Run the boundary battery with `--features panic-hook-test` on Windows
   too (the android job's pattern) — the panic→error mapping proof on the
   MSVC ABI, not just the gnu-side-host ABI the N3 run exercised.
3. Keep the header-freshness check ubuntu-side only (cbindgen regen +
   diff); duplicating it on windows adds cbindgen to a second lane for no
   new property.
4. Commit the expected headless text with its newline discipline pinned
   (LF + explicit binary-safe app-side output, or CRLF deliberately) and
   record the choice — the diff must fail on content, never on endings.
5. The N3 `local-*` ≠ `local.properties` ignore lesson has an MSVC analog:
   `.vs/` and `*.user` are the machine-local state class — scoped rules in
   condition 6 cover them; re-check the ignore set if a .sln/.vcxproj ever
   appears even though the direct-cl lane needs none.
