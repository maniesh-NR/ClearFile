# ADV-LEGAL — N3 delta-scoped gate (2026-11-27, Task N3-GATE-LEGAL)

The N3 proposal (the new separate-root `core-ffi/` crate — GPL-3.0-only,
`publish=false`, the one flat C ABI with a cbindgen-generated `clearfile.h`,
cdylib + the thin `cfg(android)` JNI shim; `apps/android/` — Gradle,
KMP-shaped with exactly ONE Kotlin target, Android Views, the SAF viewer
demo, MD3-from-seed via the palette FFI, the full honesty-surface set; the
CI android job with SHA-pinned actions and zero uploads; nothing tagged,
shipped, or version-moved) is reviewed against ADR-017's settlement and
licensing annex, the N2 `apps/linux` precedent, and my lane's standing
rules. The architecture is exactly the settlement's FFI seam (one flat C
ABI, cbindgen header, thin JNI shim, KMP Android-only, Linux direct) and
nothing in it is legally unsound. ONE MATERIAL FACTUAL FINDING: the
proposal states cbindgen is "MIT OR Apache-2.0" — **REFUTED LIVE** by three
independent probes (crates.io per-version API: `license: 'MPL-2.0'`;
mozilla/cbindgen master `Cargo.toml`: `license = "MPL-2.0"`; a single
LICENSE file at master with LICENSE-APACHE/LICENSE-MIT both 404 — a dual
MIT/Apache repo conventionally ships both). cbindgen is **MPL-2.0** — a
Mozilla project. The corrected posture is still clean — MPL-2.0 is
GPL-3.0-compatible (file-level weak copyleft; combining into a GPL-3.0
Larger Work permitted; FSF license list) and cbindgen is a BUILD-time-only
dependency, never linked into the cdylib and never distributed — but the N2
precedent's closed deny.toml allow-list (12 ids) does NOT include MPL-2.0,
so the first live cargo-deny run would fail closed on cbindgen, and every
in-tree record must state the true license. The honesty surfaces hold (the
no-AI/no-network claim is TRUE for this app in the strongest form — an
Android app that requests no INTERNET permission cannot make network
connections at all; SAF is a system Binder service, not network); the
manifest deferral is the recorded rule and nothing conveys; the version
planes stay put. The conditions below bind the two execution sessions.

**VERDICT: PROCEED-WITH-CONDITIONS (8 conditions)**

   everywhere before it lands in any record.** cbindgen is **MPL-2.0**, not

   https://crates.io/api/v1/crates/cbindgen/0.29.4` → `license:
   'MPL-2.0'`; `https://raw.githubusercontent.com/mozilla/cbindgen/master/Cargo.toml`
   → `license = "MPL-2.0"`; one LICENSE file, LICENSE-APACHE/LICENSE-MIT

   (file-level copyleft, Larger-Work combining permitted) AND cbindgen is
   build-time-only (never linked into the cdylib, never distributed). But
   every in-tree record — the core-ffi Cargo.toml comment, the deny.toml

## Risks register

(a) **The stated-license-as-fact class (exhibit A: this gate).** The
proposal's cbindgen premise was wrong; every license claim in a proposal is
a claim, not a fact. The deny.toml-from-first-commit + first-live-green-run
pattern (condition 2) is the standing tripwire — it would have caught this
on the first run (fail-closed on MPL-2.0); do not transcribe license claims
from proposals into records.

(b) **Apache-2.0 §4.1 + GPL §6 at first conveyance.** The first conveyed
Android artifact — ANY APK (a GitHub artifact, a Play track, a side-loaded
share) — is the trigger: the per-platform LICENSES manifest must bundle the
Apache-2.0 full text (the MCU-derived palette INSIDE the .so — the
THIRD-PARTY-NOTICES entry is its in-tree attribution), the Kotlin
stdlib/AndroidX notices, and the §6 corresponding-source offer extended to
name the exact crate + gradle dependency versions. "The manifest lands with
the first tagged release" (ADR-017 l.545) — until then nothing conveyable
may be uploaded (condition 7).

(c) **The no-network claim drift (Android).** The claim is OS-enforced only
while the manifest keeps zero network permissions; any future permission
addition (ads, update checks, Play services) falsifies the in-app note —
the note must change in the same commit (the D12 single-source discipline
applied to the absence note).

(d) **cargo-deny semantics drift (carried).** The closed-list OR/LicenseRef
satisfaction is version-sensitive; the MPL-2.0 finding is the proof the
design fails closed correctly; the first and every CI run is the tripwire.

(e) **The two-MD3-statements discipline (carried).** The design language is
unprotectable while the palette CODE is protected expression riding the
Apache-2.0 path — the Android theme consumes the palette FFI, so the
THIRD-PARTY-NOTICES entry is what keeps both statements true; keep it with
any theme evolution. No Google/Material logos in the app (ADR-017 annex).

(f) **MPL-2.0 attaches only if cbindgen source is ever vendored INTO the
tree** (§3 notices + file-level copyleft) — the no-vendoring rule stands;
build-dep only. Same class: never vendor Android SDK / AndroidX source.

(g) **Accidental conveyance vectors:** gradle `publish`/maven plugins, CI
artifact or cache uploads, Play tracks — none may emit a downloadable; the
android job's outputs stay runner-local.

(h) **The SDK terms drift:** the text is live-updated (last-modified
2026-04-30); re-read it at the first live android build (condition 8).
