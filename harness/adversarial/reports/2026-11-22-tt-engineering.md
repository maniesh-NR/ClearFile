## Findings

1. **[MINOR] Phase-1 note offset error.** `2026-11-22-tt-targets-phase1.md:22` states "file offset 0x99280 = overlay start"; the actual magic/overlay start is **0x99000 = 626,688 B** (byte-verified in both USA targets; consistent with the note's own overlay arithmetic and `phase1_survey.json`). This note is T2's entry map — a wrong offset in it is exactly the kind of claim §6 says must cite bytes. Fix: a dated erratum appended in T2's first doc commit.
2. **[MINOR] T3 spec placement is ambiguous.** Nothing records where T3's format-family specs land (`docs/re-research/` like the T1 notes, or `docs/formats/` per protocol §6); the Stage-2 exit checkable counts `ls docs/formats/*.md ≥ 4` **with the named files**, so TT specs under `docs/formats/` would pollute the count surface and blur the never-silently-grows rule. Compounding overlap: the Stage-2 DoD's 4th named spec (`tax-modern.md`, public-write-up shape level) is the same family T3 will spec deeply. Needs an explicit disposition now, not at T3.
3. **[MINOR] Web-side T4 would violate ADR-016 (ruling on the scope question).** ADR-016's text: "no NEW web-engine features"; allowed flows are enumerated — bug/security fixes, staged Stage-5 hardening, envelope version-guard compliance, and parameter corrections mirroring the reference through shared fixtures ("corrections never land as independent web-side feature work"). A TT read/edit/save bridge on the web side is a **new file-format feature**, not a parity correction: **BLOCKED** under the freeze. The unblocked paths are the Flutter reference app (the shipping target per the stack rules) and, later, the Rust core's WASM path (ADR-017 N6).
4. **[MINOR] Disk headroom discipline must be structural in T2.** 2.1 GB free vs four 333–404 MB overlays whose decompressed payloads can plausibly exceed 1 GB (plus any Ghidra checkpoint dirs). The T1 session already practiced deletion ("archive zips deleted after extraction"); T2's extraction must make it a rule: selective per-record/per-module extraction, immediate intermediate deletion, `df -h /` before/after, never full-overlay decompression, never two targets' payloads resident at once.
5. **[NOTE] T1 evidence quality: exemplary.** Every structural claim I spot-checked re-derived byte-for-byte (carve math, section tables, entropies, timestamps, magic, record layout, function pipeline with error-string address cross-checks, 7z/Deflate markers, CAN container shapes, TTConfig.ini facts, sha256s, the no-literal-magic claim, "not byte-identical" stubs). The limitations section is honest and matches REA's own evidence metadata. The stub-carving technique is sound and is the correct §4.A/C-avoiding move; whole-file 333–404 MB Ghidra imports must stay out permanently for this program.
6. **[NOTE] ADR-020 is well-formed as a risk acceptance**: owner instruction + trace, full risk register (§1201(a)(2)/(b), *321 Studios* analog, Canadian C-11 TPM regime, EULA claims, practical enforcement), non-negotiable boundary conditions (password-gated surface, quarantined single key module, §7.2/§7.4 unchanged, enforcement-response plan), overturn path, and dated in-file protocol amendments (verified present).
