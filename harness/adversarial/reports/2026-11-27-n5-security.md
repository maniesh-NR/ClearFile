## Risks register

1. **Runner-image drift + the `-latest` remap** (the README itself warns the
   migration is gradual, l.96): macos-latest silently moving to macOS 27
   would move the lane's OS, Xcode, and triple at once. The fail-closed
   host-triple guard turns any remap into a red naming the value — and
   NOTE: the same remap ALREADY rides the SHIPPED Flutter macOS lane
   (release.yml l.339, runs-on: macos-latest) — an existing posture
   outside this delta, but one recorded line is owed at N5's close.
2. **Blind authoring (the accepted trade).** No Swift exists in this
   sandbox — the first compile is the CI run, and the off-by-one symlink
   literal in this very proposal is a live demonstration of the error
   class. Mitigations: the fail-closed guards (the five-round N4 precedent
   says rounds are likely, and the honest CI-fix record is required); the
   boundary battery runs on the Darwin ABI; the byte-parity smoke.
3. **The 512 MiB RAM hazard** applies verbatim (the standing note): the
   uniform bound is the recorded policy; the app-side pre-read refusal is
   the honest UX, the core boundary the backstop.
4. **The smoke's CWD coupling** (condition 6): the relative-path stack
   (DYLD_LIBRARY_PATH, fixture, exe, install name) resolves against one
   working directory — a single cd anywhere in the step silently reds.
   Pinning + recording the exact invocation is the one-line mitigation.
5. **Verification concentration.** The whole macOS verification story is one
   lane on one image family, single-maintainer — the bar ruling records
   exactly this risk; any GA re-opens the owner-side-build question by
   construction.
6. **Swift EOL traps are milder than Windows** (POSIX stdout: no CRT
   text-mode translation; print() emits LF) — the both-sides `tr -d '\r'`
   normalization stays as cheap insurance; the diff must fail on content,
   never endings (the N4 lesson).
