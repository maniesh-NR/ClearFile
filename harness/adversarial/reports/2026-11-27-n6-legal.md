The N6 proposal (the Rust core serves the web via wasm32-unknown-unknown
— core-ffi compiled to wasm over the SAME flat C ABI, ONE new additive
export `clearfile_alloc` freed by the existing `clearfile_free`, NO
wasm-bindgen, no new crates, the std-only zero-dep posture holding; a
hand-rolled zero-npm-dependency JS loader/adapter in `src/lib/wasm/`;
the TS engine retiring per ADR-016 — Shape A: the engine + the TS codecs
(txf.ts/taxfile.ts/cfr.ts) become FROZEN TRANSITION ARTIFACTS (a dated
RETIRED banner, out of the import graph, still tsc-checked); Shape B:
only engine.ts retires, the codecs stay as recorded debt; the parity +
bridge suites transferring to the wasm adapter over the same fixtures +
the same behavioral contracts; hygiene's suites job + release.yml's
nextjs-web job gaining wasm build steps, release.yml's byte-freeze
re-ruled; pages.yml untouched (the Pages demo stays the Flutter app);
the terminal freeze declaration at the epilogue close (v2.0.0-territory;
v2.0.0 itself GA-gated); the TWELFTH slip surfacing with the explicit
parking posture; the ONE-session execution box) is reviewed against
ADR-016, ADR-017 (incl. the ADR-009 disposition row l.517 and the
licensing annex l.537–555), ADR-009's ratification record, my standing
register (the N1–N5 entry/exit reports), and STATE's N6 agenda
l.363–394.

The licensing posture is the SIMPLEST of the epilogue: no new crates,
no new toolchain licenses, no new vendored code. The wasm target
compiles the SAME `clearfile-core` + `core-ffi` (path-dep only; `jni` is
target-gated to android and never enters the wasm tree; cbindgen stays
build-time-only) — the Cargo.lock posture is unchanged, the zero-dep
fail-closed assertion (harness_check: core lock = exactly 1 package)
holds as-is, and cargo-deny's allow-list needs NO additions. The only
new runtime expression surface in the whole delta is the hand-rolled
loader — and the loader's pattern (fetch bytes → instantiate → allocate
in wasm memory → write input → call the flat ABI → read the owned
return → `clearfile_free`) is pure functional method-of-operation
territory (17 U.S.C. §102(b); merger; scènes à faire; *CA v. Altai*
filtration — every C-ABI wasm binding on earth is this shape, and no
third-party owns it). The DUTY is only that the *expression* stays ours:
no copied wasm-bindgen glue, no Emscripten output, no tutorial code —
condition 5 pins that fail-closed. DMCA §1201 posture is UNCHANGED by
the delta: the .wasm ships the same read-only `.tax` inspection the
core has carried since N1 (`core/src/tax_inspect.rs` l.10–12: "It
never decrypts anything… no key material, no decryptor"), ADR-020's
fixed-key transport layer stays quarantined in the TT program's own
lanes (verified: `core/src/` is engine/envelope/json/lib/palette/params/
tax_inspect/txf — no key module), and the RE lanes are untouched.

The two real legal questions of this gate are STATUS questions, not
license questions: (1) the exact FORM of the ADR-016 conversion (is a
banner on the frozen file lawful, or does the retirement live only in
the records?), and (2) the exact CONTENT and HOME of the terminal freeze
declaration. Both are ruled below with exact texts. The one genuinely
NEW conveyance fact is that the .wasm becomes the repo's FIRST Rust-core
binary with a real distribution path (the next tagged web tar.gz) —
which lights the first-conveyance LICENSES-manifest trigger ADR-017
l.545 has been deferring since N2, and surfaces a row no prior gate
needed to name (the statically-linked Rust std inside the .wasm — the
/MT precedent, CONSENSUS l.1903–1906, extended to the Rust toolchain).
