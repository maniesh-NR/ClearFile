# ADV-LEGAL — N5 delta-scoped gate (2026-11-27, Task N5-GATE-LEGAL)

The N5 proposal (apps/macos/ — ONE Swift+AppKit app per ADR-017's macOS
tiering settlement: Swift language throughout, AppKit throughout, NO
SwiftUI, deployment floor macOS 13 Ventura; an SPM package whose C target
carries core-ffi/clearfile.h as a git symlink to the SAME committed header
+ a comment-only shim.c, the Swift executable consuming it; the argv modes
+ the ONE shared pipeline + the byte-exact text family diffed against the
Linux app's committed expected text; the C-ABI ownership discipline; the
palette-FFI theme; the full honesty set; the CI macos-latest lane as the
PRIMARY verification with the named non-verifications recorded honestly;
the .gitattributes eol=lf hardening; the bar ruling formalized; the
Flutter macOS app remaining the shipped product) is reviewed against
ADR-017's licensing annex, my standing register (the N3 entry/exit + N4
entry/exit reports), and STATE's N5 agenda l.363–391.

The licensing posture is the CLEANEST of the epilogue, tied with N4: the
AppKit row is **already ruled in the annex** (DECISIONS l.542–543: "Win32
+Direct2D and AppKit are proprietary system libraries under the GPLv3 §1
carve-out" — recorded at the 2026-11-17 settlement, before any platform
code existed), and the Swift toolchain rides the cleanest license in the
stack: Apache-2.0 **with the Swift Runtime Library Exception** (verified
live 2026-11-27, below — the exception waives Apache §4 attribution for
toolchain portions embedded in binary products), GPL-3-compatible with
or without the exception. What the annex does NOT yet have is the
**Swift-toolchain sentence** — the analog of the Kotlin/Apache-2.0 row
(l.544). The Kotlin precedent was recorded in the annex *anticipating*
Android; Swift was named in the tiering row (l.512) but never given its
license sentence. That recording duty is condition 3. The one structural
N5 analog of N4's CRT question — does the built app EMBED any
Apache-licensed runtime, or link it from the OS? — is the Swift-runtime
linkage fact, decidable from the otool output at the first green run
(condition 4): with a macOS 13 floor the runtime is OS-provided and
dynamic — the no-row case — but the choice must not be silent (the /MT
precedent, CONSENSUS l.1903–1906).

The clean-room line holds. The text family (labels, groups, formats,
footer) is OUR OWN committed expression (apps/linux/tests/
expected-headless.txt, GPL-3.0-only) — porting our own text across our
own platforms is not copying; the labels themselves ("Total income",
"Adjusted gross income", the group titles) are standard IRS-form
terminology dictated by the domain — functional, unprotectable structure
under §102(b)/merger/scènes à faire, *CA v. Altai* abstraction — while our
particular footer and disclaimers are our own expression, kept byte-exact
BY our own CI contract rather than by any third-party provenance. No
third-party Swift code enters the app: JSON via Apple's system
JSONSerialization (not a hand-rolled scanner — even cleaner than N4's),
the palette via the FFI (the ONLY third-party-derived expression in the
whole epilogue stays inside our own attributed Rust module — the
THIRD-PARTY-NOTICES entry remains the single attribution), zero external
SPM dependencies. The conditions below pin that posture fail-closed
(condition 1 is the tripwire) and bind the execution session (apps/macos
ABSENT at tip 2ddcce5 — proposal-scoped gate).

The mandate areas NOT triggered by this delta, stated once: **DMCA §1201**
