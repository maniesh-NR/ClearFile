# ADV-LEGAL — N4 delta-scoped gate (2026-11-27, Task N4-GATE-LEGAL)

The N4 proposal (apps/windows/ — a C++17 Win32+Direct2D viewer demo with
ZERO external dependencies: the platform libs only, no vcpkg, no nuget, no
vendored headers — consuming the COMMITTED core-ffi/clearfile.h; the
argv/headless mode + the window mode (D2D text rows, the palette-FFI MD3
theme); the bundled fixture PULLED from the shared fixtures/tax/ family at
build time; the full honesty set; the CI windows-latest MSVC lane as the
PRIMARY verification (the fail-closed guards, cargo build --locked (the
.dll) + cargo test (the boundary battery on Windows) + the C++ compile/
link + the headless smoke with the full-stdout diff against a committed
expected text; the named non-verification: no interactive desktop run);
the local mingw lane REJECTED with the recorded second-ABI reasoning) is
reviewed against ADR-017's licensing annex (Win32+Direct2D = proprietary
system libraries under the GPLv3 §1 carve-out — the C++ lane is the annex's
own named case), my own standing register (the N3 entry + exit records: the
JUnit EPL-1.0 test-scope invariant, the first-conveyance trigger, the
THIRD-PARTY-NOTICES advisories), and STATE's N4 agenda
l.363–389. The licensing posture is the CLEANEST of the epilogue so far:
pure platform-API code against OS system libraries, consuming OUR OWN
GPL-3.0-only header and linking OUR OWN cdylib — the license surface is
entirely ours, with zero new third-party notice duties at this stage.
The mingw rejection is legally CORRECT and its licensing reinforcement
(a second header set + a second C++ runtime = a second license/notice
surface, against the annex's one-audit-surface rationale) must be recorded
with it. The one structural difference from N3: Windows has NO
manifest-permission enforcement, so the no-AI/no-network note rests on the
actual code alone — the import-table guard is what converts it from
review-trust to fail-closed. The conditions below bind the N4 execution
sessions (apps/windows/ ABSENT at tip 2a3acd1 — proposal-scoped gate).

## Conditions (numbered, checkable)

1. **The zero-third-party-consumption invariant must be ASSERTED, not
   assumed — no vcpkg, no nuget, no vendored headers, no submodules, and
   the #include set restricted to the Windows SDK + CRT.** The posture as
   proposed is all-ours + platform-only, which is exactly why it must be
   held fail-closed: any drift (a nuget JSON parser, a vcpkg library, a
   copied-in header) silently introduces the whole notice-duties class
   that this proposal legitimately avoids. The C++ side parses NO JSON
   itself — the flat ABI hands JSON strings to the core, which owns
   parsing — so there is no honest reason for any third-party include.
   *Check:* a guard (or a recorded sweep) that `rg -n
   '#include\s*"' apps/windows` returns only SDK/CRT/system headers, and
   `rg -in "vcpkg|nuget|\.gitmodules" apps/windows .github/workflows/`
   returns nothing; a dependency added later re-opens this gate's lane (a).

2. **The SPDX sweep over every new tracked file under `apps/windows/`
   (D14 + the N2-exit amendment).** Per-syntax comment forms: `.cpp`/`.h`
   `//`; `.rc` `//` (RC accepts C-style comments) or `/* */`; `.ps1`/
   `.yml`/CMake `#`; `.sln` `#` if one lands; XML (.vcxproj/.manifest)
   `<!-- -->`. Recorded un-headed classes ONLY, exactly the D14
   amendment's set: the byte-pinned expected-headless text (the direct
   analog of `apps/linux/tests/expected-headless.txt` — its bytes ARE the
   CI full-stdout-diff contract); generated lockfiles (none expected —
   the C++ lane consumes core-ffi's committed Cargo.lock, byte-unchanged);
   strict-JSON data IF a fixtures/tax byte-copy is committed (prefer the
   build-time PULL — the N3 gradle copy-task precedent: the fixture
   referenced from the build, not byte-copied into apps/windows). NO
   committed binary assets: the N3 precedent is zero binary files under
   apps/android (no launcher icon) — a Windows .ico would need a NEW
   recorded un-headed binary-asset class; prefer none (the default class
   icon) or code-generated at build time. *Check:* `git ls-files
   apps/windows` sweep returns headers on every text file except exactly
   the recorded classes; `git ls-files apps/windows | rg -i
   '\.(png|ico|jpg|jar)$'` → empty.

3. **The MSVC CRT linkage choice is RECORDED — /MD (dynamic UCRT)
   preferred.** With /MD the UCRT stays an OS System Library (GPLv3 §1
   carve-out — the same annex sentence that covers Direct2D); with /MT
   Microsoft's CRT object code is embedded in the .exe — redistribution
   is permitted by the Visual Studio/SDK terms under our own license, but
   the CRT then becomes a LICENSES-manifest row at first conveyance.
   Either is lawful; the choice must not be silent. *Check:* the link
   flags named in-tree (build script/workflow comment) and, if /MT, the
   first-conveyance checklist carries the CRT row (risk (b)).

4. **The honesty surfaces, Windows-honest in the family wording.** The
   three-fact disclaimer verbatim-in-substance from the family
   (welcome.dart / app.slint / strings.xml: not IRS-authorized; cannot
   e-file; must not be used to file a real return; + the
   qualified-professional line); the IRS/Intuit/TurboTax non-affiliation
   line; the prototype labels in the TITLE BAR + the headless header
   ("ClearFile (prototype)", the N3 launcher-label family); the
   no-AI/no-network note in the Linux app's family wording ("makes no

5. **The no-network claim needs its Windows enforcement: the
   import-table assertion (the N3-exit risk-(b) promotion).** On Android

## Risks register

(a) **The stated-license-as-fact class (carried; condition 1 is the
tripwire).** This proposal contains no third-party license claim to
refute — that is its virtue and its fragility: the all-ours surface
survives only while the zero-dependency invariant is asserted. Never
transcribe "no dependencies" from a proposal into a record without the
guard.

(b) **The first-conveyance trigger, re-stated for the Windows artifact
(carried).** The .dll embeds the Apache-2.0-derived MCU palette
(core/src/palette.rs — the THIRD-PARTY-NOTICES entry is its in-tree
attribution). The FIRST conveyed Windows artifact — ANY .exe/.dll
share: a GitHub artifact, a zip, a winget listing — triggers Apache-2.0
§4.1 (the notice in the per-platform LICENSES manifest), GPL §6 (the
corresponding-source offer naming the exact crate versions), and the CRT
row if /MT (condition 3). Until then nothing conveyable may be uploaded
(condition 7).

(c) **The no-network claim drift, now with NO OS enforcement.** Unlike
Android (OS-enforced by the zero-permission manifest), the Windows note
is true only while the code keeps zero network imports; a single drift
(auto-update, telemetry) falsifies an in-app claim. Condition 5's
import-table guard is the enforcement; without it the claim is
review-trust only.

(d) **The two-MD3-statements discipline (carried).** MD3 is unprotectable
design; the palette CODE is protected expression riding the Apache-2.0
path; the D2D theme computes from the palette FFI, so the NOTICES entry
is what keeps both statements true — keep it with any theme evolution;
no Google/Material logos (condition 4).

(e) **The mingw temptation recurrence.** The rejection is correct today;
a future "build it locally from Linux" push re-opens the second-ABI +
second-license-surface analysis. Keep the recorded reasoning where the
decision lives (condition 6) so the recurrence meets a written ruling.

(f) **The toolchain terms drift.** Microsoft's terms pages are
live-updated (verified reachable 2026-11-27); the analysis is
recorded against the current text — re-read at the first live windows
build (condition 8), the Android precedent.

(g) **Accidental conveyance vectors (carried):** CI artifact/cache
uploads, winget manifests, store registrations — none may emit a
downloadable; the windows job's outputs stay runner-local.

(h) **The byte-pinned expected-headless artifact's provenance.** Un-headed
per the D14 amendment (correct), but its bytes must be the app's honest
emission (generated by the app, pinned) — never hand-authored desired
output; the known-hash discipline applies (the expected-headless.txt
precedent).
