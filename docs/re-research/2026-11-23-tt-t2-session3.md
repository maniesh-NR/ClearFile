## The ISSetupStream v8/v7 record format — COMPLETE (byte-proven + decompile-anchored)

Extends `2026-11-22-tt-t2-session2.md`. All four ISSetupStream targets
share one grammar (the "v8"/"v7" label is the u16 at +0x0e; the u32 at
+0x10 = 4 is the record-format generation the engine dispatches on):

1. **Stream header (0x2e = 46 bytes)** at the inner installer's PE raw
   end: `ISSetupStream\0` (14 B) + `[u16 version-label 8|7]` + `[u32 4]`
   + 26 zero bytes. Engine anchor: FUN_00452b16 reads exactly 0x2e, then
   FUN_00452eda compares the first 13 chars against the
   `"InstallShield"`/`"ISSetupStream"` literals (PTR table at 0x4cc874/
   0x4cc878) and on the ISSetupStream match stores the `[u32 4]` at
   `this+0x5c`; the version dispatch then sets the record-header size
   (v4 → 0x30) and this+0x4c = 0x2e.
2. **Record (v4 generation, 0x30-byte header):**
   `[u32 nameBytelen][u32 flags=6][u16 0][u32 dsize][u32 0][u32 0]`
   `[u16 1][FILETIME ×3][UTF-16LE name (nameBytelen bytes)][payload
   (dsize bytes)]`; the next record starts at header+name+dsize. Engine
   anchors: FUN_0045374c (the v4 reader — the 0x30 read + the
   name-length read + the u32@0x0a→record+0x38), FUN_00453675 (the table
   walk; **its loop bound = the u16@0x0e version label — the table
   length is the version field itself**; 8 for the USA targets, 7 for
   CAN-Personal — both verified by the walk ending exactly there).
3. **The payload codec — decompile-derived, byte-validated on every
   record class:**
   - **Cipher (transport-layer obfuscation, name-keyed — a format fact,
     not key material):** when the record's flags field has bits 1|2 set
     (6 on every observed record) and bit 2 set, the engine decrypts
     each payload byte before inflating. The key = the record's OWN
     filename converted to UTF-8 (FUN_004534d8 → FUN_0042009f with the
     codepage id 0xfde9 = 65001 = CP_UTF8), masked bytewise with the
     4-byte constant `13 35 86 07` (FUN_0040c1c2); each data byte at
     payload offset p is then
     `plain = ~(swapnib(enc) ^ maskedKey[(p mod 1024) mod keylen])`
     (FUN_0040c10b's nibble-swap/xor/complement; the 0x3ff phase in
     FUN_00453c70 makes the keystream 1024-periodic).
   - **Compression: zlib-wrapped deflate** (the decrypted stream begins
     `78 9c`), statically linked zlib 1.2.12 (banners at 0x4acc10/
     0x4af5c0; the inflate_table lbase/dbase tables at 0x4af580/
     0x4af540 anchor FUN_0040a260 → inflate FUN_00406d70, called by the
     extract loop FUN_00406780 which also applies the record's three
     FILETIMEs via SetFileTime — proving the header FILETIME semantics).
   - Validation: `SplashScreenWithLogo409.bmp` → `78 9c` → inflates to
     a 1.4 MB `BM` bitmap; `0x0409.ini` and `Setup.ini` → UTF-16 INI
     string tables (the InstallShield message catalogs); `TurboTax
     2026.isc` → a 1,870 B binary script blob; both `.prq` records →
     InstallShield prerequisite descriptors. All decode facts
     existence-level; no content quoted.

### Erratum (T2 session 2's header arithmetic)

The session-2 note's stream-header reading "`[u32 0x36][u32 6][u32
≈0x17580000]`" was a field MISALIGNMENT: those bytes are record 1's
`[u32 54 namelen][u32 6 flags][u16 0][u32 0x1758 dsize]`. The stream
header is the plain 46-byte block; the ~391 MB "compressed size" figure
was the misread — the true measure is the record-table sum (the MSI
record's dsize 383,877,541 + the other seven records ≈ the whole
overlay). FUN_00452b16's exact 0x2e read settles it.
