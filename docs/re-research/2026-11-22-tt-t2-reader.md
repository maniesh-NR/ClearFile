## The container format (derived from the decompiles, byte-validated against TT_Personal_USA_2026.exe)

1. **@0x99000:** the 8-byte magic `48 12 90 BF 49 FF 91 AA` (built
   from immediates in the stub — not stored as a literal; re-confirmed
   by the gate's independent re-derivation).
2. **@0x99008 (6 bytes):** the internal header — `u32 = 1`;
   `u16 = 0x0200` (LE): low byte 0 → names are PLAINTEXT in this
   target; high byte 2 → the 0x100 selector.
3. **@0x9900e:** the name/value map — a flat `[u16 len][blob]` stream
   terminated by `u16 = 0`. Here: len 9 `xmlConfig`, len 483 (the
   SfxConfig XML), terminator @0x991fe. Zero-length terminator is
   FUN_00418a50's stop condition.
4. **@0x99200 — archive entries** (FUN_00418c60's parse, field-by-field
   byte-confirmed on the real target):

   | Offset | Size | Field | Observed |
   | --- | --- | --- | --- |
   | +0 | u32 | entry magic | `0x6d27e59b` (mismatch ⇒ "Found end of archive") |
   | +4 | u8 | entry type | 0x02 |
   | +5 | u16 | name length | 9 |
   | +7 | name | entry name | `SetUp.exe` (plaintext because the header flag is 0) |
   | +0x10 | u64 | FILETIME (converted Local→File) | a 2026-plausible value |
   | +0x18 | u32 | field A | 0x20 (chunk size candidate — unresolved) |
   | +0x1c | u32 | field B | 0x9e67 (compressed-size candidate — unresolved) |
   | +0x20 | … | payload stream | raw Deflate (below) |

5. **Payload codec: raw Deflate — byte-proven.** The stream at 0x99220
   inflates cleanly with zlib `wbits=-15` (zlib/gzip wrappers fail;
   adjacent start offsets fail) to `MZ` PE content: the inner
   `SetUp.exe` bootstrapper — i386, 5 sections (`.text`/`.rdata`/
   `.data`/`.rsrc`/`.reloc`), link timestamp 2026-10-15. A bounded
   decode (1 MiB in / 1 MiB out cap) yielded 90,000 bytes before the
   bound; the entry's chunking semantics (fields A/B + the stream
   layout) are the next chase. Extraction discipline per the gate
   (ENG-3): the bounded sample was written under gitignored
   `tools/re-corpus/extract/`, verified, then **deleted** (df recorded
   before/after).
6. **No encryption at this container layer for the USA targets:** the
   deflate stream needs no key; the name-encryption flag machinery
   exists (the header flag + FUN_004466e0 + the stub's
   CryptAcquireContextA import) but is OFF in this target. The
   fixed-key question therefore does not arise at the INSTALLER
   transport layer for these targets; the `.tax` crypto layer remains
   the T3/T4 study target (protocol §5, ADR-020's scope).
