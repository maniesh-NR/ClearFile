## The MSI-embedded cabinet's codec — the InstallShield MSZIP variant (byte-proven)

Extends the T2-s3 inventory (`2026-11-23-tt-t2-session3.md` §the MSI
layer). The cab's CFFOLDER table (121 records at cab[36..1004), each
`[u32 coffCFData][u16 cCFData][u16 TComp]`): **every folder carries
TComp=0x0001 (MSZIP-class)**. But the decode is NOT plain MSZIP:

1. Each CFDATA block = `[u32 csum][u16 cbData][u16 cbUncompressed]`
   followed by the 2-byte `CK` signature + a raw-deflate stream —
   the MSZIP framing.
2. **The blocks are complete streams that reference the PREVIOUS
   block's output**: a fresh raw inflate of a mid-folder block fails
   with "invalid distance too far back" (observed at folder-87 block
   61), while block 0 inflates standalone to exactly cbUncompressed —
   the distance codes reach back across the block boundary into the
   prior 32 KiB. This is the InstallShield MSI-cab variant of MSZIP:
   **the window carries across blocks**.
3. The working decoder (bench, ctypes against the system zlib 1.3.1):
   per block — `inflateReset` + `inflateSetDictionary(rolling
   last-32-KiB of output)` + `inflate(chunk)`. Validated on folder 87
   of the Personal-USA cab: **859/859 blocks CK-marked, 859/859
   complete streams, the folder inflates to exactly 28,140,152 B**
   (the arithmetic closure: the walk's cumulative cbUncompressed ends
   exactly at the folder's last file's end). The plain-MSZIP decoder is
   the empirical discriminator: it stops at 32,768 B (one block) and
   raises on the next.

This codec fact is a prerequisite for ANY future module-level
extraction from these MSIs (T3/T4 tooling included) and is recorded
here for the format-family notes.

## The .tax-layer anchors (identifier-level, the T3 findings)

The keyword census over the carved module (ASCII case-insensitive +
UTF-16LE): `.tax` 111× (.rdata) + 7× (UTF-16, .rsrc);
`password` 33× (.rdata) + 17× (UTF-16); `crypt` 373×; `ttax` 255×;
`mef` 204×; `ttx` 20×; `turbota…` 37×. The significant anchors:

1. **The `IData::` serialization family (the .tax data layer's API
   surface)** — .rdata rva 0x10caed8-class cluster:
   `IData::Open()`, `IData::ReadString(string)`,
   `IData::ReadVector(vector)`, `IData::WriteString(string)`,
   `IData::WriteVector(vector)`, `IData::Close()`, `IData::Swap()`,
   `IData::Proxy()` — the read/write primitives over the return-data
   model (the .tax layer's object I/O).
2. **Crypto++ embedded** — the .rdata exception-string cluster at
   rva 0x10cc6f8..0x10cc9b8 (StreamTransformation / RandomNumber-
   Generator / BufferedTransformation / CryptoMaterial classes +
   `SHA-256`): the crypto primitive library for the layer (a public
   open-source library's own identifiers, cited at identifier level).
3. **The password surface (user-facing + service-facing):**
   - the save-dialog string class at .rsrc rva 0x18db028 — a
     checkbox label instructing that the file be encrypted and
     password-protected (the save path's password gate; paraphrased
     per §7.4, the RVA is the citation);
   - the transfer service string at .rdata rva 0x143d4d0-class — a
     `TransferReturnServiceImpl::GetFormsetIDFromFile` diagnostic
     about setting a password on read (the open-with-password
     service path);
   - the e-file credential block `USERID` / `PASSWORD` / `ACCTNUM`
     at .rdata rva 0x10d7e50-class (a different, e-file-transmission
     context — kept distinct in the notes to avoid conflation).
4. **The managed-native bridge command namespace:** `ztfFileIO`,
   `zcmEFileCmd`, `zimTransfer::SingleConvert` (rva
   0x10d3160/0x143d3da-class) — the z-prefixed command family between
   the CEF/JS UI and the native engine (the file-I/O command surface
   the UI drives).
5. **The e-file/TaxML family** (context, not the .tax layer):
   `ETX_V12.01` (rva 0x10c86a0), `TAXML_ATTACHMENT`,
   `TURBOTAX-WINDOWS-`, the MEF converter strings — the transmission
